PART 7 — SECURITY REVIEW
====================================================

ITEM 1 — JWT_SECRET_KEY exposure              [CONCERN]
  Set as a shared env var in .replit [userenv.shared]: visible to anyone
  with access to the Replit project. Should be moved to Replit Secrets.
  Current value is 45 chars and HS256-sufficient in strength.
  Action: Move to Replit Secrets before deployment.

ITEM 2 — CORS_ORIGINS = "*"                  [CONCERN — dev only]
  Wildcard CORS is acceptable in development. MUST be locked to the
  production domain before going live. Already documented in PROJECT_STATUS.txt
  LAUNCH BLOCKERS section.

ITEM 3 — Password Hashing                    [GOOD]
  werkzeug scrypt (memory-hard, modern). Default since werkzeug 2.0.
  Verified working: hash prefix "scrypt:32768:8:1". No issues.

ITEM 4 — passlib Conflict Risk               [LOW]
  passlib is installed alongside werkzeug. Two hash formats in the same
  codebase create risk of a future developer mixing them, causing silent
  auth failures. Remove passlib from requirements to eliminate ambiguity.

ITEM 5 — Account Lockout                     [GOOD]
  5 failed logins → locked_until stored in DB (survives restarts).
  Separate from IP rate limiting. Works correctly.

ITEM 6 — IP Rate Limiting                    [ACCEPTABLE / NOTE]
  In-memory, per-process (threading.Lock). Works correctly for single-
  worker Uvicorn (current config). On multi-worker or multi-instance
  deployments the limits do not enforce globally. Documented in source.
  For current single-worker Replit setup: acceptable. Revisit for scale.

ITEM 7 — File Upload Validation              [GOOD]
  Only .pdf extensions accepted. Max file size: MAX_FILE_SIZE_MB (50MB).
  Stored filenames are UUID-randomized (no path traversal risk).
  Content-type validation relies on file extension, not MIME sniffing
  (minor weakness — could add python-magic for MIME validation).

ITEM 8 — !! DEPLOYMENT BLOCKER: .replit run  [CRITICAL]
  .replit deployment run command is:
    ["gunicorn", "--bind", "0.0.0.0:5000", "main:app"]
  This would launch the legacy Flask app (main.py → app.py) in production.
  FastAPI never starts. The entire React frontend and API would be broken.
  Fix: Update to uvicorn serving FastAPI + built frontend.

ITEM 9 — Audit Logging                       [GOOD]
  Tracks: login_success, login_failure, login_blocked, upload,
  bulk_upload, edit, delete. Primary action always succeeds even if
  the log write fails (correct design). Logs include IP address.

ITEM 10 — JWT Token Expiry                   [GOOD]
  JWT_EXPIRE_MINUTES defaults to 60. Expired tokens return 401.
  Frontend (admin.js) interceptor catches 401, clears localStorage token,
  and redirects to /admin/login. Works correctly.

ITEM 11 — No HTTPS enforcement               [NOTE]
  Replit proxy handles TLS; the app itself doesn't need to enforce HTTPS.
  ProxyFix middleware is not present in FastAPI (was in Flask). FastAPI
  runs behind Replit's proxy — acceptable.

PART 8 — PERFORMANCE REVIEW
====================================================

ITEM 1 — N+1 query: get_subjects_for_class   [CONCERN]
  Location: backend/app/api/subjects.py → get_subjects_for_class()
  For each subject in a class, a separate COUNT query is issued:
    for s in cls.subjects:
        count = db.query(Paper).filter(...).count()
  For Class 11/12 (11 subjects each) = 12 DB queries per request.
  Total for 4 classes = 48 queries if all are loaded sequentially.
  Currently hidden by zero papers in the DB.
  Fix: Single JOIN + GROUP BY paper count per subject.

ITEM 2 — N+1 query: admin stats              [LOW PRIORITY]
  admin/stats fires 7 separate COUNT queries. Could be one query with
  CASE aggregation. Admin-only view, acceptable for now.

ITEM 3 — In-memory analytics reset           [KNOWN RISK]
  analytics.py uses a module-level deque + defaultdict.
  All search analytics are lost on every restart/deploy.
  Not a correctness bug but means trend data never accumulates.
  Fix: persist to DB or Redis when needed.

ITEM 4 — In-memory rate limiter reset        [KNOWN RISK]
  rate_limit.py in-memory store resets on restart.
  An attacker could restart-DOS by triggering a restart to clear locks.
  Mitigated by DB-level account lockout (locked_until persists).

ITEM 5 — Frontend bundle size                [UNKNOWN]
  No production build (`npm run build`) has been run yet.
  No code splitting or React.lazy() implemented.
  PapersPage and DashboardPage are the heaviest components.
  Action: Run build and inspect dist/ chunk sizes before deploy.

ITEM 6 — No database query caching           [ACCEPTABLE]
  Classes and subjects are static data (seeded once). They're re-queried
  on every request. For current traffic, this is fine. For high traffic,
  a simple in-memory LRU cache on class/subject lists would be beneficial.

ITEM 7 — DB connection pool                  [GOOD]
  pool_recycle=300, pool_pre_ping=True — appropriate for Replit's
  managed PostgreSQL which closes idle connections.

ITEM 8 — Local file serving                  [NOT PROD-SAFE]
  /uploads served via FastAPI StaticFiles from the local filesystem.
  On Replit deployments, the filesystem is ephemeral — all uploaded PDFs
  are lost on redeploy. Must be replaced with cloud storage.
