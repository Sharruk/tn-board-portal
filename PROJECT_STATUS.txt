PHASE 3.6 CHANGES — Student Experience

1. View Paper button
   When public_url exists, prominent blue "View Paper" button opens
   PDF in a new browser tab (target="_blank" rel="noopener noreferrer").
   Separate from Download button so students can preview before saving.

2. Download button (improved)
   Now uses HTML download attribute for direct save.
   On click: fires POST /api/v1/papers/{id}/download to increment counter.
   Shows "Download Question Paper" or "Download Answer Key" by type.

3. Share button
   Uses Web Share API when browser supports it (mobile-native share sheet).
   Fallback: copies current page URL to clipboard.
   Success toast appears at bottom of screen for 2.8 seconds.

4. Download counter
   Backend: papers.download_count column added (migration applied).
   Endpoint: POST /api/v1/papers/{id}/download increments and returns paper.
   Frontend: count displayed below action buttons as "N downloads".
   Counter updates optimistically in UI without page reload.

5. Related papers section
   Now shows up to 4 papers from the same subject (was 3, same exam type).
   Header reads "More from [Subject Name]" with "View all →" link.
   Responsive grid: 1 col mobile → 2 col tablet → 4 col desktop.
   Reuses existing PaperCard component.

6. Toast notification
   Animated pill toast at bottom-center of screen.
   Auto-dismisses after 2.8 seconds.
   Used for Share success and clipboard copy feedback.

7. Layout improvements
   Action buttons: full-width on mobile, inline row on desktop.
   Consistent spacing (p-6 mobile, p-8 desktop).
   Share icon-only on mobile (saves space), icon + label on desktop.
   Download count shown as subtle line below buttons.
