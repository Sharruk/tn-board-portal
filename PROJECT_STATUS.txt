SLUG URL FORMAT

Pattern: /paper/{slugify(title)}-{id}

Examples:
  /paper/class-10-mathematics-annual-exam-2024-1
  /paper/class-10-science-quarterly-exam-2024-2
  /paper/class-11-physics-half-yearly-exam-2024-4

Backend lookup: rsplit('-', 1) extracts ID from end of slug.
Old numeric routes still work: /paper/1, /paper/2, etc.
All paper API responses include a computed `slug` field.

PHASE 3.8 CHANGES — Production Readiness

1. PDF-Only Platform
   config.py: ALLOWED_EXTENSIONS = {"pdf"}  (was {"pdf","doc","docx"})
   storage.py: Error message: "Only PDF files are supported."
   Frontend: file input uses accept=".pdf"
   Frontend: client-side check before submit (shows inline error)
   Backend: PDF required for new uploads (400 if missing)

2. Content Quality — Duplicate Detection
   Before inserting a new paper, admin.py checks for:
     same title + subject_id + year + exam_type
   Returns 409 Conflict if duplicate found.
   Message: "A paper with the same title, subject, year, and exam type already exists."

3. Recently Added Papers
   Homepage: "Recently Added" section shows latest 10 uploads (was 6).
   Endpoint already existed; limit increased to 10.

4. Popular Papers
   NEW endpoint: GET /api/v1/papers/popular?limit=10
   Sorts by download_count DESC, then created_at DESC.
   Homepage: "Most Downloaded" section (conditionally shown when papers exist).
   PaperCard: new `showDownloads` prop shows download count badge.

5. Admin Dashboard — Stats Cards
   NEW endpoint: GET /api/v1/admin/stats (JWT-protected)
   Returns: total_papers, total_downloads, total_subjects, total_classes,
            visible_papers, question_papers, answer_keys
   Dashboard: 4 primary cards (Papers, Downloads, Subjects, Classes)
              3 secondary cards (Q Papers, Answer Keys, Visible)

6. SEO Slug URLs
   slugify() in backend/app/schemas/schemas.py:
     - lowercases, strips non-alphanumeric, collapses hyphens
   slug is a @computed_field @property on PaperOut and SearchResult.
   All paper API responses automatically include slug.
   NEW endpoint: GET /api/v1/papers/by-slug/{slug}
     Extracts ID from slug suffix, looks up paper by ID.
   Frontend: PaperCard links use slug URL if available.
   Frontend: PaperDetailPage detects numeric vs. slug param (regex check).

7. PDF Preview (PaperDetailPage — already complete from Phase 3.6)
   View Paper → opens PDF in new tab
   Download PDF → HTML download attribute + records download count
   Share → Web Share API / clipboard fallback
