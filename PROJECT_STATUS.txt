PHASE 4.1 — PRODUCTION SECURITY HARDENING (complete)

1. Admin Account (admin credentials replaced)
   * Admin created with email: hungrylearner786@gmail.com
   * Username changed from "admin" to "hungrylearner"
   * Password is bcrypt-hashed (never stored in plain text)
   * Login accepts either username OR email in the username field
   * Script: change_admin_password.py (interactive, never prints password)

2. IP-Level Rate Limiting (backend/app/services/rate_limit.py)
   * 5 failed login attempts from same IP within 15 minutes
     → IP locked for 15 minutes
   * Returns HTTP 429 with Retry-After header and human-readable message
   * Resets automatically on successful login from that IP
   * In-memory (per-process); swap for Redis for multi-worker deployments

3. Account Lockout (stored in database)
   * 5 failed password attempts → admin.locked_until set (15 min)
   * Persists across server restarts (stored in admins table)
   * Successful login resets: failed_login_count=0, locked_until=NULL
   * Returns HTTP 423 (Locked) with minutes remaining

4. Audit Logging (audit_logs table + backend/app/services/audit.py)
   Actions recorded:
     login_success   — successful login (IP, timestamp, email)
     login_failure   — wrong credentials (IP, identifier attempted)
     login_blocked   — account locked (prevented from even checking password)
     upload          — paper uploaded (paper id, title, exam_type, year)
     bulk_upload     — paper uploaded via bulk upload tab (same fields)
     edit            — paper metadata changed (paper id, changed fields)
     delete          — paper deleted (paper id, title)
   Fields: admin_id, admin_email, action, target_paper_id,
           target_details (JSON), ip_address, timestamp
   Logging failures are swallowed — primary action always succeeds.

5. Session Security
   * JWT access tokens expire after JWT_EXPIRE_MINUTES (default: 60)
   * Configurable via JWT_EXPIRE_MINUTES environment variable
   * Expired tokens return HTTP 401 "Session expired. Please log in again."
   * Frontend ProtectedRoute redirects to /admin/login on any 401

6. Admin Dashboard Additions
   * Admin identity panel (top-right): email + "Last login: [date]"
   * Admin Actions Log card: last 30 events with action badge, paper
     title, masked IP, and relative timestamp ("5m ago", "2h ago")
   * "First session" shown until first login recorded

7. Documentation
   * change_admin_password.py — interactive script to safely change password
     or email, unlock account; never stores or echoes password in source
   * backend/migrate_41.py — one-time migration script (already run)
   * PROJECT_STATUS.txt — this file
