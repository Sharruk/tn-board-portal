# Sprint Tracking

This folder contains the planning and tracking documents for the project, starting with Version 2.

## How it works

1. **BACKLOG.md**: This file acts as the master list of all planned features, technical debt, and bugs. It is maintained across sprints.
2. **Sprint Reports (SPRINT_XX.md)**: Each sprint gets its own document (e.g., `SPRINT_00.md`, `SPRINT_01.md`). These files document the goals, architecture planning, tasks, and progress for that specific sprint.
3. **Review & Guidance**: Future sprint reports and planning documents are kept in this folder so that the AI (ChatGPT/Claude/Gemini) can easily review our progress, understand the current state of the architecture, and effectively guide the next sprint.

Always update `BACKLOG.md` when new requirements are discovered, and keep the current sprint document updated with progress.
