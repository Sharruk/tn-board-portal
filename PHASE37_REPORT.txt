TASK 4 — SEARCH ANALYTICS

STATUS: COMPLETE

Changes made:
  backend/app/services/analytics.py  (new file)
    - Thread-safe in-memory store using threading.Lock
    - _recent: deque(maxlen=20) — last 20 search events
    - _counts: defaultdict(int) — per-term search count
    - track_search(term, result_count) — called on each search
    - get_analytics() — returns popular_searches + recent_searches

  backend/app/api/admin.py
    - GET /admin/search-analytics endpoint added
    - Protected by get_current_admin (JWT required)
    - Returns: { popular_searches: [{term, count}], recent_searches: [...] }

  frontend/src/services/admin.js
    - getSearchAnalytics() added

  frontend/src/pages/admin/DashboardPage.jsx
    - Popular Searches card added (right column, 1/3 width)
    - Fetches from /admin/search-analytics on mount
    - Shows top 10 terms with count badges (e.g. "mathematics  3×")
    - Empty state: "No searches yet. Stats appear after students search."

Note: Analytics are in-memory. They reset on backend restart.
This is intentional for the current phase (no persistent analytics DB).
