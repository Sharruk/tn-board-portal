PHASE 4.2 — Full Project Audit, Cleanup & Architecture Review

Goal:

Before deployment, perform a complete audit of the entire codebase and generate a detailed report.

Do NOT deploy anything.
Do NOT add new features.
Do NOT change business logic unless removing dead code.

====================================================
PART 1 — PROJECT INVENTORY
==========================

Generate a complete inventory report.

Document:

1. Frontend

   * Framework used
   * Routing system
   * State management
   * UI libraries
   * Component structure
   * Services layer
   * Pages
   * Admin pages

2. Backend

   * Framework used
   * Database ORM
   * Authentication system
   * JWT implementation
   * API structure
   * Middleware
   * Storage system

3. Database

   * All tables
   * Relationships
   * Indexes
   * Current row counts

4. Infrastructure

   * Environment variables
   * Storage providers
   * Deployment configuration
   * Build configuration

====================================================
PART 2 — DEAD CODE DETECTION
============================

Search entire repository for:

1. Flask code

   * Flask app.py
   * Flask routes
   * Flask templates
   * Flask static folders

2. Old HTML files

   * Standalone HTML pages
   * Unused templates

3. Unused React files

4. Unused CSS files

5. Unused JS files

6. Duplicate components

7. Duplicate API endpoints

8. Unused services

9. Abandoned experiments

10. Temporary debugging files

11. Test/demo/sample files no longer used

====================================================
PART 3 — DEPENDENCY AUDIT
=========================

Analyze:

requirements.txt

package.json

Report:

1. Installed but unused packages
2. Duplicate packages
3. Deprecated packages
4. Security concerns
5. Packages safe to remove

====================================================
PART 4 — FILE STRUCTURE REVIEW
==============================

Generate complete project tree.

Mark each item as:

ACTIVE
UNUSED
UNKNOWN

Example:

frontend/
ACTIVE

frontend/src/pages/
ACTIVE

old_flask_app/
UNUSED

====================================================
PART 5 — SECURITY REVIEW
========================

Verify:

* JWT implementation
* Password hashing
* Rate limiting
* Audit logging
* Environment variables
* Secret handling
* CORS
* File upload validation

Report any issues.

====================================================
PART 6 — PERFORMANCE REVIEW
===========================

Check:

* Duplicate queries
* N+1 query issues
* Unused API calls
* Large bundle issues
* Unused frontend assets

====================================================
PART 7 — CLEANUP PLAN
=====================

DO NOT DELETE ANYTHING YET.

Instead produce:

Cleanup Candidate List

For every file/folder:

SAFE TO DELETE
LIKELY SAFE
NEEDS REVIEW
KEEP

Explain why.

====================================================
PART 8 — FINAL REPORT
=====================

Create:

PROJECT_AUDIT_REPORT.txt

Include:

1. Tech Stack Summary
2. Architecture Diagram
3. Folder Structure
4. Dead Code Findings
5. Dependency Findings
6. Security Findings
7. Performance Findings
8. Cleanup Recommendations
9. Deployment Readiness Score

Do not modify files automatically.

First generate the audit report.

After the report is complete, wait for approval before deleting anything.
